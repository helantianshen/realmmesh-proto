# 账户变更通知 RPC v1

协议定义位于 [auth.proto](auth.proto)。本次新增订阅协议待审查，中心广播与 Mod 订阅尚未实现；已有注册登录协议不变。

## 订阅与字段

服务端流 RPC：`/realmmesh.auth.v1.AuthService/SubscribeAccountEvents`。

请求 `SubscribeAccountEventsRequest` 为空。每个游戏服运行实例订阅一次，服务器身份沿用 metadata 中的 `x-realmmesh-server-id` 和 `authorization: Bearer <server_secret>`。请求不携带在线玩家列表、服务器 ID、筛选条件或历史游标。

| 事件字段 | 类型 | 含义 |
| --- | --- | --- |
| `player_name` | `string` | 账户原始大小写名字，按现有 3–16 位 ASCII 名字规则校验，忽略大小写匹配 |
| `reason` | `AccountEventReason` | `PASSWORD_CHANGED` 表示改密成功，`ACCOUNT_DELETED` 表示账户逻辑删除成功 |

中心仅在数据库变更提交成功后向当前订阅者广播，不向失败或回滚的操作发送通知。客户端建立 Channel 不等于订阅已就绪；服务端应在登记订阅后发送响应头，调用方据此区分建流成功与仅开始调用。无账户变更时不发送空事件充当心跳。

## 游戏服处理

1. 网络回调将事件交给服务器线程，处理前确认回调仍属于当前运行实例和有效订阅，停服或替换订阅后丢弃旧回调。
2. 校验名字及原因。空名字、非法名字、零值或未知原因不执行踢出，只记录不含敏感内容的诊断信息。
3. 按忽略大小写的名字查找当前在线玩家，无论其是否已登录，均清除认证状态、取消在途注册登录请求，再断开连接，避免迟到认证响应重新放行。
4. 改密提示“账户密码已变更，请重新进入并登录”；删除提示“账户已删除，连接已断开”。玩家不在线时无需操作，也不记录待踢出队列。

所有订阅服务器均处理通知，不只通知变更来源服务器。同一账户多服在线时，各服分别处理。重复通知不依赖事件编号去重；断开已经离线的玩家无需再次执行。

## 生命周期与错误

建流和每次发送前复用中心既有服务器认证。凭据缺失、停用、删除或轮换后，返回 `Unauthenticated`；依赖故障使用 `Unavailable`，内部错误使用 `Internal`，客户端取消使用 `Canceled`。空闲流在下次收发检查时发现凭据撤销，不承诺即时关闭。

订阅不复用普通 Unary RPC 的短调用期限。停服主动取消；意外结束后由 Mod 异步、有限频率重建，避免并行重复订阅及无间隔重试。网络恢复不踢出既有玩家，不重新认证，不追赶漏掉的通知。

通知是尽力发送，无确认、离线队列、持久化事件表或补发机制。发送失败不回滚已经成功的账户变更；实现需隔离慢订阅者，不能让一个游戏服阻塞其他订阅或账户事务。不保证数据库提交与游戏服踢出原子完成。

## 账户变更与命令边界

- 玩家自助改密必须校验旧密码；普通注册登录权限不能替代旧密码验证
- 首期删除账户仅允许中心管理员，Minecraft OP 不自动具有中心管理员权限
- 前端尚未开发，本步不增加 HTTP API；后续仅按实际入口需求补齐必要接口
- 未注册或未登录玩家只能使用 `/realmmesh register`、`/realmmesh login`，不能使用本模组其他命令，OP 也不例外
- 直接修改数据库不触发事件；已有 HTTP JWT 不因通知而撤销
